# 2026-10-09 — the tower hub state as a provenance surface

**Asked.** What do `.tower/comms/` records carry, and what do they prove? (lane
`HubStateReceipts`, scout.)

**Observed.** Hub at the **repo root**: `/home/vgpnk/Projects/ompskills/.tower/comms/`.

| record | shape |
| --- | --- |
| `missions/M*.md` | generated header (`:3` “update via the TowerMission tool”); row `Branch \| Worktree \| Status \| Scope \| Owner`; sections `## Context — the user's own words, verbatim`, `## Tasks` (`- [x]`), `## Dependencies`, `## Blockers`, `## Notes`. Rendered from `state.json` `missions[]` `{id,title,slug,kind,scope[],branch,worktree,deps[],status,context,tasks[{text,done}],notes[],blockers[],owner}` |
| `reviews/review-<branch>-<reviewer>-r<round>.md` | YAML front matter `date, reviewer, target, round, seq, status, merge, reviewed_commit` (full 40-hex), `mission, tokens`; `## Findings`, `## Checks` (each `- [x]` + the command/claim **and its observed result**), `## Decision`. Hand-authored (no generated marker) |
| `findings/<YYYYMMDD>-<agent>-<type>-<slug>.md` | header `Date, Agent, Type, Severity, Mission, Tokens`; `## Summary`, `## Location`, `## Details`, `## Suggested Fix / Action`, `## Why Not Fixed Directly`; footer `*Filed by tower agent <name> …*`. `Type ∈ {bug, improve}`; `Severity ∈ {low, medium, high}` |
| `log/activity.log` | append-only, one line per event: UTC `Z` stamp + actor + verb + fields + `ref=<path>`. **The only place a sequence of state changes is recorded** — `state.json` and `MISSIONS.md` hold only the current value |

`state.json` top-level keys: `version, base, mode, createdAt, sessionId, roster,
missions`; `.roster.agents[]` = `name, agentId, sessionId, kind, missionId,
worktree, branch, spawnedAt`.

**Generated-header rule** (convention only — plain Markdown/JSON, a hand edit
would be indistinguishable): `MISSIONS.md:3` `<!-- Generated by tower tools from
state.json — do not edit by hand. -->`; each `missions/M*.md:3` `<!-- … update via
the TowerMission tool. -->`. Corroborating mtime evidence: `MISSIONS.md` and
`state.json` share `19:14:48.306Z`, matching the `activity.log` line
`… merge … merge_commit=d035dee` at `19:14:48.307Z` — the hub is **regenerated on
each state transition**.

**Scope map** (`MISSIONS.md:21-25`): one glob set per mission (M1 `**`
“informational, reserves nothing”; M2 `host/**`; M3 `.omp/skills/**`; M4 `test/**,
test/evidence/.gitignore`); **mutable by the coordinator** — the log shows
`merge.blocked reason=out-of-scope` followed by a `mission.update scope=…`.
**Status vocabulary** (`:12`): planned · active · completed · blocked · paused ·
merged · abandoned (legend emoji→word); `state.json` stores the word.

**Proves.** A mission was declared and assigned (roster binding + a `tower spawn`
line); status transitions occurred via tool calls (UTC-stamped log + actor); a
review was written by a named reviewer at a specific full-SHA `reviewed_commit` in
a numbered round/seq, with `## Checks` recording commands **and observed results**;
a finding was filed by a named agent with type/severity/path; artifacts are
cross-referenced by `ref=` path.

**Does not prove.** Correctness (every status/`done`/`Checks` entry is a
self-reported claim); what landed (`reviewed_commit` ≠ the merge commit: M4
`7fab95b` vs `d035dee`); the full merge path (M4’s review reads `clean`/`merge`
while the log shows a blocked-then-widened intermediate); evidence contents (the
hub stores path references, not bytes or hashes); record integrity (no signature).
