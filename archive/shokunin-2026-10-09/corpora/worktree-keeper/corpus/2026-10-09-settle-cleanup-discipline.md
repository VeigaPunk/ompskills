# 2026-10-09 — the complete tower settle/cleanup discipline as one statement

**Asked.** State the complete settle/cleanup discipline for tower fleets: what is preserved, what may be removed, the exact forbidden commands, and the per-path removal rule — cited to `.omp/skills/tower/SKILL.md` and `sighting/tower-fleet.mjs`.
**Sources.** `.omp/skills/tower/SKILL.md:98-120,169-172`; `sighting/tower-fleet.mjs:22-24,1195,1209,1220-1224` (`verbClose`); `sighting/l1-prompt.md:163-166`; corpus `2026-10-09-worktree-hazards.md` (I1-I4), `2026-10-09-tower-settle-cleanup.md`, `2026-10-09-launcher-close-manual-only.md`.
**Observed.** The discipline, as a single ordered contract both sources agree on (drift flagged inline):

1. **Settle before touching anything.** Track each created worktree and assignment through completion; collect the worker's actual handoff, inspect its changes in its own worktree, record failures honestly (`SKILL.md:100-102`). A failed worker is recovered only inside its original disjoint assignment, reusing its existing worktree where safe — no silent scope widening, no duplicating an active writer (`:102-104`). On interruption, preserve the branch and worktree **including uncommitted changes**, re-establish state, never discard unintegrated work (`:105-107`); the parent alone integrates and verifies (`:107-108`).
2. **Inspect, then preview, before any cleanup** — `omp worktree list --json` and `omp worktree clear --dry-run` (`SKILL.md:110-112`, `l1-prompt.md:163-164`). **Drift:** those verbs scan only the agent yard (`worktree.base`, default `~/.omp/wt`) and return `[]` / "No orphaned worktrees to remove." against a repo holding dozens of fleet trees — the truthful inspector is `git -C <repo> worktree list [--porcelain]` (see `-tower-settle-cleanup`, `-wt-list-semantics`).
3. **Preserved, always:** useful unmerged work; unresolved changes are reported, not discarded (`SKILL.md:112-113`); the mission branch (it survives tree removal — see `-wt-retire-by-path`); any tree whose safe targeted cleanup cannot be established — leave it intact and report plainly, with exact state and the resume command (`SKILL.md:118-120`).
4. **Removable:** only a worktree whose work is settled and no longer needed (`SKILL.md:113-114`) — and removal is never automatic: `close --apply` mutates only the wall (its sole shell-out is wall `complete`, `:1195`); in JSON it reports `worktreeRemoval: "manual-only"` (`:1209`), in human mode it prints the warning plus one retire line per mission (`:1220-1224`). Launcher header: "worktrees are only ever removed by the operator with the exact per-path command this tool prints, never automatically" (`:22-24`). **Drift:** `SKILL.md:171-172` says a failing wall `complete` "aborts first" — the code records the per-mission failure, continues, then raises `COMPLETE_FAILED` (exit 2) (`:1197-1204,:1226-1229`; also the `MUTATION_REQUIRES_APPLY` message falsely says close "mutates the wall and the worktrees", `:1267`).
5. **Exact forbidden commands:** (a) **`omp worktree clear --all`** — never; it clears every entry, including live PR-checkout worktrees (`SKILL.md:117-118`, `l1-prompt.md:166`, omp help `--all` text); (b) **`omp worktree clear` as a per-path retire** — never the way to retire one worker's tree; the sweep is yard-scoped, not repo-wide, and cannot be aimed at a path (empirically the PATH arg is silently ignored, exit 0 — hazards I2); the launcher's own header bans the verb outright: "never `omp worktree clear` (repo-wide sweep)" (`:22`), and its close output says "retire its worktree by path only — never `omp worktree clear`" (`:1221`); (c) **no automatic removal at all** — no omp verb, no launcher verb, no lane removes a tree (`:1209,:1220`; hazards I3).
6. **Per-path removal rule.** Command: `git -C <repo> worktree remove <path>`, one tree at a time, by its own path, only after its work is settled and unmerged work is preserved (inspect, integrate, or keep the branch — `:1220`; `SKILL.md:114-116,169-171`). Git fails closed: a dirty tree is refused with exit 128 ("contains modified or untracked files, use `--force`") — `--force` is the only discard door and is forbidden on a tree carrying uncommitted work (hazards I4, empirical in scratch repo).
