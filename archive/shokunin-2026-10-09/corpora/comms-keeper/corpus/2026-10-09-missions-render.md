# 2026-10-09 — what generates MISSIONS.md and missions/M*.md

**Asked.** Prove the generator of the two "generated" files and when it runs.
**Sources.** `protocol__store.ts.js:895-930` `renderMissionsIndex`, `:931-965` `renderMissionFile`; call sites `:124, :342-343, :426-427, :632-633, :728-729, :787-788`; reimplementation diffed against hub A.
**Observed.**
- Both are full-file `writeFile` overwrites from `state.json`. A /tmp reimplementation of both templates rendered hub A's `state.json` **byte-identical** to `MISSIONS.md` and all 4 `missions/M*.md` (`cmp` exit 0).
- Headers (exact bytes from the binary): index `<!-- Generated by tower tools from state.json — do not edit by hand. -->`; mission file `<!-- Generated by tower tools from state.json — update via the TowerMission tool. -->`.
- Index: `# MISSIONS`, table `| ID | Mission | Branch | Worktree | Status | Owner |` (owner fallback `—`), legend `Status: 🟡 planned · 🔵 active · 🟢 completed · 🔴 blocked · ⏸️ paused · ✅ merged · 🚫 abandoned`, `Mode: <mode> — Base: <base>`, `## Dependency Flow` (`<dep> → <id>` per edge, else `(none)`), `## Scope Map` (`- <id>[ (survey — informational, reserves nothing)]: <globs>`).
- Mission file: `# Mission <id>: <title>[ — (read-only survey)]`, row `| Branch | Worktree | Status | Scope | Owner |`, `## Context — the user's own words, verbatim` (only if set), `## Tasks` (`- [x]`, `- [ ]`, `- [-] … (dropped)`), `## Dependencies`, `## Blockers`, `## Notes`.
- Rendered at: fresh init (index only), plan, every `updateMission` (incl. `silent`, which only suppresses the log line), non-clean review that flips completed→active, survey merge, build merge. **Not** rendered on `rebase`, `adopt`, `release`, `registerAgent`, `markAgentDied`, teardown — so the hub is not regenerated "on each state transition".
- `MISSIONS.md` is **never read** by any tool. `missions/M*.md` **is** read back by `TowerMission` (read) and injected into spawn briefings — a hand edit there is trusted until the next render overwrites it.
