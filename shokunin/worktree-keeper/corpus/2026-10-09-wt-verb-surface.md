# 2026-10-09 — `omp worktree` verb surface (from the CLI)

**Asked.** Enumerate the complete `omp worktree` verb surface from the CLI itself.
**Sources.** `omp worktree --help` (and `-h`, `add --help`, `list --help`, `clear --help`, `omp wt --help`); action probes.
**Observed.**
- Actions are exactly three: **`list` (default), `clear`, `add`** — the set is closed (`omp worktree bogus` → `error: Expected action to be one of: list, clear, add; got "bogus"`). **There is NO per-path `remove`/`rm`/`prune`** — `omp worktree remove|rm|prune …` exit 1 with the same "Expected action …" error. Path-scoped removal is plain `git worktree remove`; registry-scoped removal is `clear`.
- Flags and owning action: `-C/--cwd` add; `-b/--branch` add (create-new only — an existing branch errors); `-B/--force-branch` add (reset; `-b`+`-B` → exit 1 fatal); `-d/--detach` add; `-q/--quiet` add (help lacks the `(add)` tag); `--all` clear; `-n/--dry-run` clear; `-j/--json` list+clear only (inert for add). Flags are **not** validated per action (`list --all`, `add --all`, `clear -b x` are accepted silently).
- Usage line: `$ omp worktree [ACTION] [PATH] [COMMIT] [FLAGS]`; 8 EXAMPLE lines verbatim in help (`omp worktree`; `omp worktree list --json`; `omp worktree add ../feature`; `omp worktree add -b feature ../feature origin/main`; `omp worktree add --detach ../review HEAD~2`; `omp worktree clear`; `omp worktree clear --dry-run`; `omp worktree clear --all`). Help text is **identical** for every variant (`--help`/`-h`/`add --help`/`list --help`/`clear --help`), and `omp wt` is a static alias of `omp worktree`.
- Exit codes: 0 for help / `list` / `clear --dry-run` / `add` success; the **post-checkout hook's own exit code** on a failing hook (observed 3); 1 for a bad action, unknown flag, missing path, existing path, `-b`+`-B`, bad commit, non-repository, or a checked-out branch.
- Drift: `list` reads the agent registry (`OMP_WORKTREE_DIR` > `worktree.base` > `~/.omp/wt`), not `git worktree list`, and `add` does not register there → `.tower/*` worktrees are invisible to `omp worktree list`/`clear`; `-j` is documented globally but inert for `add`; `-C` and PATH are not tilde-expanded (`not a repository: /tmp/~`; a literal `~` dir is created); clone-first prints `Cloned from <root> via reflink` on btrfs but the FICLONE warning + plain checkout on tmpfs, and a PATH containing `~` makes the warning text degenerate into an unbounded repeated path.
