**Sources.** live probes; the ELF strings dump (`/tmp/omp-strings.txt`); `sighting/tower-fleet.mjs:806-811,1220-1223`.
**Observed.**
- omp's worktree subsystem is **agent-scoped scratch lifecycle management**: a private, CoW-cloned, self-GC'ing yard (`~/.omp/wt`, overridable via `worktree.base`/`OMP_WORKTREE_DIR`) holding four consumer kinds — session `wt/*` trees, subagent task-isolation sandboxes, github `pr-<num>` checkouts, and security-scan targets — with in-band capture (the bash tool rewrites `git worktree add` → `omp worktree add`) and orphan-first machine-global GC (`clear`, with `--all` as an escape hatch).
- Base resolution verbatim: `process.env.OMP_WORKTREE_DIR ?? worktree.base ?? rootSubdir("wt","data")` (strings `$338180`). Definitive intent sentence (`$554136`): "Base directory for agent-managed worktrees — task-isolation copies, github PR checkouts, and omp worktree cleanup all live here. Unset uses ~/.omp/wt… OMP_WORKTREE_DIR env var overrides this."
- `list --json` kinds observed: `pr-checkout` (ANY healthy linked tree, incl. manual adds), `stray`, `empty`; the `task-isolation` kind + markers `.omp-isolation-owner.json` / dirs `m`,`merged` in code (`$613072`,`$915441`,`$915510`). `clear` default filter is orphan-only (`e.all ? t : t.filter(a => a.orphanReason !== undefined)`, `$915325`); live pr-checkouts are removed via `worktreeRemove(path,true)` only under `--all`; no branch deletion in the clear path [INFERENCE].
- **Decisive contrast:** trees placed **outside** the base dir (via `omp add` or plain `git worktree add`) are invisible to `omp worktree list`; `grep -c '\.tower'` in the binary strings = 0 — omp has zero awareness of the tower convention. tower-fleet deliberately uses only the `add` constructor and opts out of custody by placing trees inside `<repo>/.tower/worktrees`, where omp's `list`/`clear` structurally cannot see them (creation `tower-fleet.mjs:806-811`; close prints `git -C <repo> worktree remove <path>`, never omp `clear` :1220-1223).
- `session-worktree.ts` (decompiled): branch `wt/YYYYMMDD-HHMMSS` (`$739281`); `onExit remove` only if `!dirty && !moved && !offBranch` else prompt; session-exit removal deletes the branch (`$739420-$739423`) — the **opposite** of tower's branch-is-ledger discipline (tower never auto-deletes a branch; Mercator removal keeps it).
