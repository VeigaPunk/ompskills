# 2026-10-09 — what `omp worktree list` actually enumerates

**Asked.** Determine exactly what `omp worktree list` enumerates.
**Sources.** live probes (bare, `--json`, `-C <repo>`, from `/tmp`, with `OMP_WORKTREE_DIR` set); binary strings for the config description; `sighting/tower-fleet.mjs:798,805-811,1221-1223`; peers WtNoRemoveVerb / WtStrings.
**Observed.**
- `omp worktree list` does **not** enumerate a repo's git worktrees. It scans the immediate children of the agent-managed worktree base directory — default `~/.omp/wt`, config key `worktree.base`, env override `OMP_WORKTREE_DIR` (binary config description: "Base directory for agent-managed worktrees — task-isolation copies, github PR checkouts, and `omp worktree cleanup` all live here. Unset uses `~/.omp/wt`… `OMP_WORKTREE_DIR` env var overrides this") — and classifies each dir by its `.git` contents. It never opens the current repo; `-C` is documented `(add)`-only and inert for `list` (same output for `-C /nonexistent`, exit 0).
- Repo reality vs the verb: `git -C ompskills worktree list` → 38 entries (36 under `.tower/worktrees/`, plus main and `/tmp/cov-r2/gitdemo/trees/w1`); `ls ~/.omp/wt` → missing (exit 2). Bare `omp worktree list` (from the repo, from `/tmp`, and as bare `omp worktree`) → "No agent-managed worktrees found under /home/vgpnk/.omp/wt." exit 0.
- `--json` → `[]` (`od -c`: `[ ] \n`) exit 0; an empty dir yields the same message with the resolved dir interpolated; a base dir pointing at a **file** → ENOTDIR Bun stack trace, exit 1.
- An `omp worktree add -C /tmp/wtp/base -b probe/one /tmp/wtp/trees/one` → exit 0 ("Cloned … via reflink"), visible to `git worktree list`, **invisible** to `omp worktree list` even with `-C /tmp/wtp/base`; nothing is written to `~/.omp/wt`. → `add` (explicit PATH) never registers into the managed root.
- Registry contents: with `OMP_WORKTREE_DIR=/tmp/fakewt` and one real add inside it — "live /tmp/fakewt/live-one · wtcln · live/one" plus orphaned entries ("parent repo no longer tracks this worktree"; a stray "no recognizable worktree contents"); summary "1 live · 2 orphaned · 3 total"; JSON row shape `{path, kind(pr-checkout|stray), parentRepo?, branch?, orphanReason?}`.
- Falsification: `tower/SKILL.md:110-111` ("Before any cleanup, inspect with `omp worktree list` (`--json` for machine reading)") — repeated at `l1-prompt.md:163-164` — is falsified for tower lanes: following it against this 38-worktree repo yields `[]`/exit 0, i.e. total blindness to every `tower/<fleet>/<id>` mission tree (the launcher itself never uses `omp list`; it checks `existsSync` :798 and prints `git worktree remove` :1221-1223). Related drift: `SKILL.md:115`'s "repo-wide orphan sweep" is wrong — `omp worktree clear` sweeps only the base dir, not the repo (`clear --dry-run -C ompskills` → "No orphaned worktrees to remove." with 38 live trees; it *would* remove synthetic entries inside `OMP_WORKTREE_DIR`).
- Correct inspector: `git -C <repo> worktree list [--porcelain]` for inventory, `git status`/`log` per tree, `fleet.json` + wall for fleet truth, and per-path `git -C <repo> worktree remove <path>` for retirement; `omp worktree list`/`clear` remain valid only for the `~/.omp/wt` omp-managed pool.
