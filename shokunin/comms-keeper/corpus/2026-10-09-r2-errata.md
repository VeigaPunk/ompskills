  (omits `isReservedTowerAgentName` and `TOWER_NAME`). — FalsifyAnchors
- **Hub location.** A hub sits at the kimi session's **cwd**
  (`resolveTowerRepoRoot` strips `/.tower/worktrees/` only; no git-toplevel
  lookup), not "the repo root of wherever kimi ran". Hub B proves it: cwd
  `/home/vgpnk`, repo `~/.git` on `master`. — FalsifyHubBRounds
- **TowerSpawn writes.** Each worker spawn also runs silent `updateMission`
  calls (spawnBase, status=active+owner) → `state.json` + `MISSIONS.md` +
  mission-file re-render; `silent` gates only the log line
  (`protocol__store.ts.js:425-428`). Plus a `died` line if the agent was
  already terminal at spawn (`spawnTool:197`). — FalsifyWriters
- **Resume logging.** A tower resume of an agent with a recorded non-completed
  death logs `revived` (`SubagentStarted` → `clearAgentDied`,
  `store:278-295`, gated by `diedAt`). Only resumes of live agents are
  unlogged. Card :125 and :129 fixed; also falsifies "tower resumes" in the
  Unlogged list. — FalsifyLogGrammar, FalsifyMergeGate
- **harness-scout boundary.** harness-scout covers **omp** sessions only
  (`grep kimi` → 0 hits). kimi session stores are comms-keeper's own domain.
  Card :171 fixed. — FalsifyBoundaries
- **Read-path trust.** `readInbox` filters on frontmatter `type: inbox` + `to`,
  no filename or sender check; `reviewsFor` trusts the `review-<slug>-r<n>.md`
  filename prefix and integer round; `merge` checks `status: clean` +
  `reviewed_commit == tip`, never reviewer identity. Card :186-189 rewritten.
  — FalsifyWriteGuard

## Corrections accepted (corpus-level; original entries stand, this entry amends)

- **Finding schema enforced at runtime.** `"(schema only)"` was wrong: tool
  args pass Ajv validation (`preflightToolCall`, `kimi.strings:1089010/
  1089057`) against the zod-derived JSON Schema before `resolveExecution` —
  out-of-enum `severity` is rejected at call time. Only `fileFinding`'s own
  internal path skips it. Required fields: `type,title,summary,details,
  suggested_fix` (the corpus list omitted `type`). — FalsifyFindings
- **Inbox frontmatter.** `tokens` is always rendered
  (`String(input.tokens ?? -1)`); only `scope`, `action`, `consent_ref` are
  omitted when undefined. Hub A: all 22 files carry `tokens:`. —
  FalsifyInbox
- **Survey title suffix.** Mission-file title suffix is ` 🔍 (read-only
  survey)` (space U+1F50D space), not ` — (read-only survey)` — the latter
  occurs 0 times in the binary. Hub M1 confirms. — FalsifyTemplates
- **Enter/adopt preconditions.** `adopt` at `towerService.ts.js:203` runs only
  after: main-agent check, experiment flag, feature-assembled check,
  `prepareUserBase` (throws on base conflicts), already-active early return
  (`entered:true`, **no** adopt), and the owner check (`owned-by-live-session`
  refusal or `takeover` exit). `adoptForeignRoster` itself no-ops if
  `state.json` is missing or already owned by this session. — FalsifyOwnership
- **Mode-change deletion.** `/tower on` *does* delete: `adoptForeignRoster`
  splices out every roster entry whose `sessionId` differs. `/tower off`
  clears `sessionId` only. The sparse-mode reminder also names `MISSIONS.md`
  and `activity.log` (only inbox/findings/reviews are exclusive to the full
  text). Verbatim stop doctrine: "when two consecutive rounds report the same
  findings, stop the loop" (round cap 5 in the same sentence). —
  FalsifyModeStatus
- **Naming collisions.** The `-2`…`-100` `wx`-open suffix applies to inbox,
  findings, and reviews only; mission files are `writeFile` (overwrite, no
  suffix). Real-file count grew to 70 (69/70 reproduce; the misfit is the
  hub-A stray). — FalsifyNames
- **Merge-gate unlogged refusals.** Beyond `block()` codes: `no tower mission
  owns branch` (store :714, thrown raw), all `GitError` throws
  (`diffNameOnly`/`branchTip`/`mergeNoFf`), and `load()`'s
  `tower is not initialized` escape `merge.blocked` logging. — FalsifyMergeGate
- **Error surface.** `spawnTool.ts.js:232` has its own inline
  `TowerProtocolError|GitError` catch; the other 10 tools share
  `runTowerTool`. "All via runTowerTool" was wrong. — FalsifyRefusals
- **review-request search.** `findReviewRequest` is called from two briefing
  paths: the reviewer briefing *and* `workerHistorySection` for a respawned
  worker's predecessor review-request (`spawnTool:329` and `:342`).
  The 50-scan limit holds. — FalsifyMessageFlow
- **Doctrine bytes.** Triage line verbatim: `Finding → triage: assign to a
  mission, plan a new one, or backlog — the disposition is your call; tell the
  human.` (U+2192, U+2014 — not the ASCII-ish paraphrase in findings-routing).
  — FalsifyMessageFlow
- **Sender check on emptied rosters.** After an adopt, `state.json` roster is
  empty by design; flagging senders absent from the live roster misfires on
  every hub-B file (15 misfits). The recipe's sender set is `spawn name=` ∪
  `adopt … retired=` from the log, not the live roster. — FalsifyHazards
- **Timeline precision.** r1-verdict→merge gap is 50.4 s, not 51 s
  (log :41→:44). — FalsifyHubATimeline
