**Observed**

- Form: `ufo-sighting peek --mission RUN_OR_MISSION [--lines N]`. `--mission` is required
  (`{type:"missionId", required:true}`); `peek takes no command after --` for a positional.
- `--lines`: int, `default 80`, `min 1`, `max 400`, **clamp: true** → `Math.min(400, Math.max(1, n))`.
  Out-of-range integers are **silently clamped** (0→1, -3→1, 99999→400), not refused; only a blank or
  non-safe-integer value fails `INVALID_ARGUMENT "--lines must be an integer"`. Both constants are
  code-only (`surface.mjs:20,22`); no config key.
- Argument order is observable: `--lines` is validated **before** mission resolution
  (`peek --mission Nope --lines 1.5` reports the `--lines` error, not `MISSION_NOT_FOUND`).
- Output: raw pane text on stdout via `capture-pane -p -t <paneId> -S -<lines>`, normalized by
  `stripCapturePadding` (drop a trailing empty line, strip blank tail lines, at most one trailing `\n`;
  empty capture → empty stdout). This is the one "render" verb that does **not** print a JSON envelope.
- Lock: the whole resolve → liveness → `liveOwnedPane` → `capture-pane` runs inside `withOperationLock`,
  so a concurrent `stop`/`remove` cannot swap the row mid-check; hold time is bounded by the 400-line
  clamp and `runTmux`'s 8 MiB `maxBuffer`.
- Refusals (stderr, exit 2): `INVALID_ARGUMENT` (no command / missing `--mission` / unknown flag / bad
  `--lines` / blank `--lines`), `MISSION_NOT_FOUND` (absent manifest, or no matching row),
  `MISSION_AMBIGUOUS` (identifier matches >1 row), `MISSION_NOT_LIVE` (status not `starting|running`),
  `DEAD_PANE` (no bound pane / pane not alive / `panePid` drift), `TMUX_ERROR`, `WALL_BUSY`,
  `FOREIGN_SESSION`, `UNSAFE_STATE`, `MALFORMED_MANIFEST`, `FOREIGN_STATE`, `INVALID_ENVIRONMENT`,
  `INVALID_TMUX_SOCKET` (via `runTmux`).
- Declared state map: `live → render`; `stopped`/`completed → MISSION_NOT_LIVE`; `absent →
  MISSION_NOT_FOUND`; `live_without_live_pane → DEAD_PANE`; `live_pane_in_copy_mode → render`
  (`capture-pane` reads copy mode — peek does **not** refuse copy mode, unlike `steer`'s `PANE_IN_MODE`).
- The draft advisory `ufo/docs/advisory/2026-09-17-ufo-improvement-pack/01-sighting-surface-and-tick.md`
  claims a copy-mode refusal and `absent → MISSION_NOT_LIVE`; the shipped code and live `surface --json`
  do **not** — code + live manifest win.
